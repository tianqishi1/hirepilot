# HirePilot 技术实现方案

> 对应《产品设计方案》MVP v0.1 ｜ 2026-11-20

## 1. 架构总览

```
┌────────────────────────────────────────────────────────────────┐
│  Spring Boot 3 业务后台 (Java 17, :8080)                        │
│  职位/候选人/审核队列/任务编排/看板 REST API                     │
│  PostgreSQL(生产) / H2-PG兼容模式(开发)                          │
└──────────────▲─────────────────────────────▲───────────────────┘
               │ REST (领取任务/回传结果/心跳) │ REST (HR 操作)
┌──────────────┴───────────────┐   ┌─────────┴─────────┐
│  Python Agent Worker         │   │  HR / 看板 (P1 UI) │
│  ┌────────────────────────┐  │   └───────────────────┘
│  │ Pipeline 状态机         │  │
│  │ discover→extract→score │  │        ┌──────────────────────┐
│  │ →review→greet→chat     │  │        │ LLM 服务(OpenAI兼容)  │
│  ├────────────────────────┤  │◄──────►│ qwen-plus / 任意兼容  │
│  │ 执行层(按优先级降级)     │  │        │ qwen-vl-max(视觉)     │
│  │ 1 DOM: Playwright      │  │        │ 无Key→MockLLM(离线)   │
│  │ 2 视觉: 截图+VLM+坐标   │  │        └──────────────────────┘
│  │ 3 桌面RPA / 4 移动端(P1)│  │
│  ├────────────────────────┤  │        ┌──────────────────────┐
│  │ 稳定性: 重试/幂等/断点  │  │───────►│ Mock 招聘站 (:9000)   │
│  │ 截图留证/心跳/运行报表  │  │        │ 动态DOM/抖动/模拟回复 │
│  └────────────────────────┘  │        └──────────────────────┘
└──────────────────────────────┘
```

**关键决策**
| 决策 | 选择 | 理由 |
|---|---|---|
| 主干语言 | Java 17 + Spring Boot 3.3 | 对齐目标岗位技术栈；业务系统长期可维护 |
| 执行器语言 | Python 3.12 + Playwright | 自动化/AI 生态最强；与后台经 REST 解耦，可独立横向扩容 |
| 队列 | MVP 用 DB 任务表 + 轮询 | 少一个中间件；P1 换 Redis Stream/RabbitMQ 不改接口 |
| LLM 接入 | OpenAI 兼容 /chat/completions (httpx) | 一套代码通吃 DashScope/OpenAI/本地 vLLM；无 Key 自动 MockLLM |
| 硬条件过滤 | 规则引擎（代码）而非 LLM | 护栏指标"误触达≤1%"必须确定性保证 |
| 视觉降级 | 截图→VLM 输出坐标→鼠标点击 | DOM 失效时的通用兜底，路线可解释可回放 |
| 开发数据库 | H2 (PostgreSQL 兼容模式) | 零安装跑通；生产 profile 切 PostgreSQL，JPA 屏蔽差异 |

## 3. 数据模型（JPA 实体）

| 实体 | 关键字段 | 说明 |
|---|---|---|
| Job | title, jdText, hardFilters(JSON), rubric(JSON), greetingStyle, dailyLimit, status | 职位与筛选标准 |
| Candidate | jobId, externalId, name, resumeText, profile(JSON), score, scoreReason, status, dedupeKey | 唯一约束 (jobId, externalId) 防重复建档 |
| ReviewItem | candidateId, proposedMessage, decision(PENDING/APPROVED/REJECTED), reviewerNote | 人工审核队列 |
| ChatMessage | candidateId, direction(IN/OUT), content, intent, idempotencyKey UNIQUE | 幂等发送的落地凭证 |
| TaskRun | jobId, workerId, state, stats(JSON), startedAt, finishedAt, heartbeatAt | 一次执行批次 |
| Incident | taskRunId, kind, detail, screenshotPath | 异常留证 |

候选人状态机与 PRD §5 一致；状态迁移全部经 service 层校验，非法迁移抛 409。

## 4. REST API 设计（MVP）

```
# HR 侧
POST /api/jobs                      建职位(JD+硬条件+rubric)
GET  /api/jobs                      职位列表
GET  /api/candidates?jobId=&status= 候选人列表
GET  /api/reviews?decision=PENDING  审核队列
POST /api/reviews/{id}/approve      批准(可改写话术) → 候选人 APPROVED
POST /api/reviews/{id}/reject       否决 → CLOSED
GET  /api/dashboard?jobId=          漏斗计数+成功率

# Worker 侧（MVP 共享同一 API，P1 加 worker token）
POST /api/worker/tasks/claim        领取任务(行级锁防并发重复领取)
POST /api/worker/tasks/{id}/heartbeat
POST /api/worker/tasks/{id}/finish  回传统计
POST /api/worker/candidates         批量 upsert 候选人(按 dedupeKey 幂等)
POST /api/worker/messages           回传消息(idempotencyKey 去重)
POST /api/worker/status             状态迁移(非法迁移409)
POST /api/worker/incidents          上报异常+截图路径
GET  /api/worker/approved?jobId=    拉取已批准待发送的候选人
```

Worker 离线模式：后台不可达时自动切换 standalone，把同构结果写入 `worker/out/run-*.json`，保证演示与开发不依赖 Java 环境。

## 5. Agent 执行循环（worker/pipeline.py）

```
for candidate in discover(job):            # 列表页翻页, 语义选择器(role/text)
    if dedupe.seen(key): continue          # 本地幂等 + 后台唯一约束双保险
    resume = extract(candidate_url)        # DOM 抽取; 失败→视觉路线读屏
    profile = llm.extract(resume)          # 结构化: 年限/学历/技能/期望
    hard_pass, reasons = rules.check(profile, job.hardFilters)   # 确定性护栏
    score, reason = llm.score(profile, job.rubric)               # 0-100 + 可解释理由
    if not hard_pass or score < reject_line: archive(REJECTED)
    else:
        msg = llm.greet(profile, job)      # 个性化打招呼(含自动消息声明)
        submit_review(candidate, msg)      # 进入人工审核队列
for c in approved_candidates():            # 第二阶段: 执行已批准触达
    send_message(c, idempotency_key=sha1(job+c+msg))   # 重试不重发
for c in greeted_candidates():             # 第三阶段: 收回复→意图→应答/转人工
    intent = llm.classify(reply)           # FAQ / 意向 / 敏感 / 无关
    FAQ→llm.answer(job.faq) 自动回; 敏感→ESCALATED 转人工
```

**降级策略**：每个页面操作封装为 `act(locator, visual_hint)`：
1. Playwright 语义定位（get_by_role/get_by_text，抗 class 混淆）；
2. 超时/异常 → 截图 + VLM(`visual_hint`) 返回 bbox → 坐标点击/读屏；
3. 仍失败 → 抛 `StepFailure`，保留截图与 HTML 快照，任务挂起上报 Incident，绝不静默跳过。

## 6. 稳定性工程（对齐 JD 第 5 条）

| 机制 | 实现 |
|---|---|
| 重试 | 指数退避装饰器 `@retry(times=3, base=1s)`，仅对网络/超时类异常重试 |
| 幂等 | 消息 idempotencyKey 唯一约束；候选人 dedupeKey upsert；本地 seen 集合断点续跑 |
| 断点 | 每步完成即写 checkpoint(JSON)；重启从上次候选人继续 |
| 留证 | 失败自动截图 + page.content() 快照到 out/incidents/ |
| 心跳 | 每 30s 上报 heartbeat；后台判定超时任务可回收 |
| 限速 | 每次触达间 sleep 抖动(2-5s)，dailyLimit 硬上限 |
| 可观测 | 运行结束输出 stats：发现/评分/拒绝/待审/发送/回复/降级/失败 计数 |

## 7. LLM 评估与评测

- **抽取 prompt**：输出严格 JSON（年限、学历、技能列表、期望薪资、亮点），temperature=0。
- **打分 rubric**（职位可配权重）：技能匹配 40 / 经验相关性 30 / 年限学历 20 / 稳定性 10；输出 `{score, reasons[], risks[]}`。硬条件不达标直接规则拒绝，LLM 分数仅作排序。
- **话术生成**：引用候选人 1-2 个真实亮点 + 职位卖点，≤120 字，尾部自动消息声明。
- **评测**（worker/eval/run_eval.py）：标注集 `dataset.jsonl`（简历原文 + 人工 shortlist 标签 + 期望分档），指标：shortlist 准确率、硬性条件误放行数（必须=0）、分数 MAE。MockLLM 与真实 LLM 共用同一评测入口，模型/prompt 改动先跑回归再上线。

## 8. Mock 招聘站（测试替身）

FastAPI 实现，刻意复刻真实站的"脏"：
- class 名每次渲染带随机后缀（`btn-a3f9`），逼迫使用语义选择器；
- 列表懒加载 + 分页；简历页结构不一致（两种模板）；
- `/api/chat/send` 20% 概率返回 503（演示重试+幂等）；
- 候选人脚本化自动回复（含 FAQ、谈薪敏感、无关闲聊三类，驱动意图分支）。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 真实平台反爬/协议 | 开源演示只打 Mock 站；生产走官方 API/授权 RPA（产品红线） |
| LLM 幻觉打分 | 硬条件规则兜底 + 人工审核队列 + 评测回归 |
| 页面改版 | 语义选择器 + 视觉降级 + Incident 留证，三层防线 |
| 骚扰候选人 | 限速/去重/黑名单/自动消息声明 |
| Java 环境缺失 | 后端容器化；Worker standalone 模式保证可演示 |

## 11. 路线图

- P1：Redis 队列、worker 鉴权、看板 UI、钉钉告警、桌面 RPA 执行器（Windows UIA）。
- P2：移动端执行器（ADB+Appium）、选择器自愈（失败样本→VLM 生成新定位→灰度验证）、多模型评估对比、约面日历集成。

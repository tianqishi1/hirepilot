# HirePilot 产品设计方案

> AI 招聘运营自动化 Agent 平台 —— 让 HR 从"翻简历、打招呼、回消息"中解放出来，只做判断和决策。
> 版本：MVP v0.1 ｜ 日期：2026-11-20

## 1. 背景与问题

招聘运营（尤其蓝领/校招/大批量社招）中，HR 的时间大量消耗在低价值重复劳动上：

| 环节 | 现状痛点 | 耗时占比（访谈估计） |
|---|---|---|
| 筛简历 | 平台列表逐条点开，关键词肉眼匹配，标准不一致 | ~40% |
| 打招呼/邀约 | 复制粘贴模板话术，无个性化，回复率低 | ~25% |
| 多轮沟通 | 候选人问题高度重复（薪资/地点/工时），人工逐条回 | ~25% |
| 记录与跟进 | 手动记 Excel，漏跟进、重复触达 | ~10% |

同时，市面 RPA 脚本普遍"一改版就挂"，缺乏评估与可观测性，HR 不敢放权。

## 2. 产品定位与目标用户

- **定位**：Human-in-the-loop 的招聘运营自动化 Agent。机器做执行与初筛，人做标准制定与最终决策。
- **目标用户**：
  - 主用户：中小企业 HR / 招聘专员（日均触达 50+ 候选人）
  - 次用户：招聘负责人（看漏斗报表、定筛选标准）
  - 内部用户：自动化工程师（维护执行器、处理异常）
- **不做什么（边界）**：不做招聘平台本身；不做全自动发 offer；不绕过平台风控做未授权抓取（见 §8 合规）。

## 3. 核心用户故事

1. 作为 HR，我创建一个职位并写下 JD 与硬性条件（学历/年限/技能），系统按统一 rubric 自动给候选人打分并给出**可解释理由**。
2. 作为 HR，我在"待审核队列"里批量确认/否决 AI 的触达建议，确认后 Agent 自动发送个性化打招呼。
3. 作为 HR，候选人回复常见问题时 Agent 自动应答；遇到超纲问题（谈薪、投诉）自动转人工并提醒我。
4. 作为招聘负责人，我看到漏斗看板：触达→回复→意向→约面，以及 AI 初筛与人工复核的一致率。
5. 作为工程师，页面改版导致执行失败时，系统自动降级到视觉 Agent 路线；仍失败则挂起任务、保留现场截图并告警，而不是静默丢数据。

## 4. 功能地图与 MVP 切分

| 模块 | MVP（本期） | P1 | P2 |
|---|---|---|---|
| 职位管理 | 职位 CRUD + JD + 筛选 rubric 配置 | 多职位并行、优先级 | 职位模板库 |
| 候选人 CRM | 自动建档、去重、状态机 | 标签/搜索、黑名单 | 人才库激活 |
| 简历评估 | LLM 结构化抽取 + rubric 打分 + 理由 | 评估集回归、偏差审计 | 多模型对比 |
| 触达执行 | 浏览器自动化打招呼（审核后发送） | 定时/限速策略、A/B 话术 | 移动端 App 执行 |
| 自动沟通 | 常见问题自动回复 + 转人工 | 约面日历集成 | 语音外呼 |
| 审核队列 | 触达前人工确认、超纲消息转人工 | 批量操作、抽检 | 自动放行阈值 |
| 稳定性 | 重试/幂等/断点/截图留证/心跳 | 告警通知（钉钉/飞书） | 选择器自愈 |
| 看板 | 漏斗计数 + 任务运行报表 | 一致率/回复率趋势 | ROI 测算 |
| 执行路线 | DOM(Playwright) + 视觉 Agent 降级 | 桌面 RPA | 移动端(ADB/Appium) |

## 5. 核心流程

```
HR 建职位(JD+硬性条件+话术风格)
        │
        ▼
Agent 领取任务 ──► 候选人列表页翻页发现 ──► 打开简历页抽取原文
        │                                      │
        │                              LLM 结构化抽取 + rubric 打分
        │                                      │
        │                    ┌── 不达标 ──► 归档(原因入库)
        │                    │
        │              达标/边界 ──► 生成个性化打招呼 ──► 【人工审核队列】
        │                                                  │ HR 批准
        │                                                  ▼
        │                                          浏览器发送(幂等)
        │                                                  │ 候选人回复
        │                                                  ▼
        │                                     意图理解 ──► 常见问题: LLM 自动回复
        │                                             └► 超纲/敏感: 转人工 + 提醒
        ▼
 全程: 心跳/重试/断点/截图留证 ──► 运行报表 + 漏斗看板
```

**候选人状态机**：`DISCOVERED → SCORED → (REJECTED | PENDING_REVIEW) → APPROVED → GREETED → CHATTING → (INTERVIEW | ESCALATED | CLOSED)`

## 6. 关键界面（MVP 为 API + 简易看板，UI 属 P1）

1. **职位列表/详情**：JD、rubric 权重、话术风格、每日触达上限。
2. **审核队列**：候选人卡片（评分、理由、拟发送话术）＋ 批准/否决/改写。
3. **候选人详情**：简历原文、评分明细、完整聊天记录、操作留痕。
4. **运行看板**：今日任务数、成功率、降级次数、漏斗计数、异常列表（含截图）。

## 7. 成功指标（北极星与护栏）

| 指标 | 目标 | 说明 |
|---|---|---|
| HR 人均日触达量 | ≥ 3× | 北极星：效率提升 |
| 打招呼回复率 | ≥ 人工模板 ×1.3 | 个性化话术价值 |
| AI 初筛-人工复核一致率 | ≥ 85% | 评估集 + 线上抽检 |
| 误触达率（硬性条件不符仍发送） | ≤ 1% | 护栏：硬条件用规则兜底，不交给 LLM |
| 任务成功率（含降级） | ≥ 98% | 稳定性 |
| 转人工响应时长 | ≤ 5 min（工作时间） | 体验护栏 |

## 8. 合规与安全边界（产品红线）

1. **演示与开源仓库一律使用自建 Mock 招聘站**；对真实平台的生产化必须走官方 API 或获得授权的 RPA，遵守平台协议与 robots。
2. 候选人数据最小化采集；简历属个人信息，落地需脱敏存储、可删除（被遗忘权）。
3. 自动回复必须可识别为自动消息（话术尾部声明），敏感话题（薪资承诺、合同条款）一律转人工。
4. 触达频率限速 + 黑名单 + 去重，杜绝骚扰式群发。
5. LLM 评估仅作初筛建议，拒绝决策保留人工抽检通道，避免算法歧视。

## 9. 里程碑

- **W1-2（本仓库 MVP）**：Mock 站 + Worker 执行闭环 + LLM 评估 + Spring Boot 后台 + 审核队列 API + 评测脚本。
- **W3-4**：视觉 Agent 降级实战化、自动沟通状态机完善、看板 UI。
- **W5-6**：评估集扩到 100 份、稳定性加固（告警/断点恢复演练）、移动端 demo、演示视频。
